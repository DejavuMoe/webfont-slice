# WebFont Slice

[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [한국어](README.ko.md) · **日本語**

中国語・日本語・韓国語の Web フォントを必要なときだけ読み込む WOFF2 シャードに分割し、そのまま配備できる `unicode-range` CSS を生成します。ラテン文字の本文フォントとコード用等幅フォントは文字体系ごとに分割し、リガチャとスタイルセットはそのまま保ちます。処理はすべてブラウザ内で完結し、フォントがアップロードされることはありません。

ソースコード: <https://github.com/DejavuMoe/webfont-slice>（MIT）

![Noto Sans SC Variable を読み込んだ WebFont Slice の作業画面](docs/images/workbench-cjk.png)

CJK フォントは 1 つで 7〜20 MB にもなります。WebFont Slice は実際のコーパス頻度から各文字がページに現れる確率を見積もり、動的計画法でどこで切るかを決めます。その結果、ページは実際に描画するグリフだけをダウンロードします。

| 収録範囲（Noto Sans SC Variable） | 文字数 | 単一ファイル（実測） | 記事ページの実測ダウンロード（1,500 字） | 単一ファイル比 |
| --------------------------------- | -----: | -------------------: | ---------------------------------------: | -------------: |
| 常用（汎用規範漢字表 1 級）       |  3,701 |               945 KB |                   810 KB · 12.5 ファイル |           −14% |
| 完全（汎用規範漢字表 全表）       |  8,306 |              2.13 MB |                   868 KB · 14.9 ファイル |           −60% |
| GBK（文字集合ライブラリ）         | 21,124 |              5.37 MB |                   879 KB · 15.1 ファイル |           −84% |
| すべて（フォントの全グリフ）      | 30,890 |              7.41 MB |                   891 KB · 15.1 ファイル |           −88% |

ページあたりのダウンロード量は文字集合の大きさにほとんど左右されません。3 千字から 3 万字に広げても、記事ページは 80 KB ほど増えるだけです。この数値は `pnpm benchmark:planner --measure` によるもので、全シャードを実際にサブセット化したうえで頻度から期待値を計算しています。手法と他のフォントについては [`docs/SHARDING.md`](docs/SHARDING.md) を参照してください。

### ラテン文字フォントとコードフォント

漢字を含まないフォント（ラテン文字の本文フォント、JetBrains Mono や Fira Code のような等幅コードフォント、アイコン入りの Nerd Font）は自動的に判別されます。収録範囲は Unicode ブロック単位の 4 段階、テキストのみ・西欧・多言語（ラテン拡張・ギリシア・キリルを追加）・すべてに切り替わります。中間の 2 段階はフォントが実際に持つ文字だけを取るので、何百個もの幽霊のような「欠字」が出ることはありません。ASCII と一般的な約物は基本シャードに入り、残りは文字体系ごとにまとめられます。ギリシア文字、キリル文字、罫線と矢印、私用領域のアイコンがそれぞれ独立したシャードになり、英語だけのページは通常基本シャードだけを読み込みます。

| フォント（すべての文字） | 文字数 | シャード数 | 単一ファイル（実測） | ページが通常読む量 |
| ------------------------ | -----: | ---------: | -------------------: | -----------------: |
| JetBrains Mono 2.304     |  1,363 |          5 |                55 KB | 19 KB 基本シャード |
| Fira Code 6.2            |  1,586 |          6 |                67 KB | 23 KB 基本シャード |

等幅フォントはその旨が表示されます。「レイアウト機能を保持」が有効なとき（既定）は `calt`/`liga` のリガチャに加えて `ss01`–`ss20` のスタイルセットと `cv01`–`cv99` の文字バリアントも保持されるため、自分の CSS から `font-feature-settings` で切り替えられます。生成される使用例は等幅の書体ファミリーを `code, kbd, samp, pre` に対応づけ、結果ページと `demo.html` はコードサンプルでプレビューします。

## 3 つの手順

1. **フォントをドロップ**: TTF、OTF、WOFF、WOFF2 をファイルシグネチャで判別し、1 ファイル 100 MB まで。同じファミリーの複数のウェイトをまとめて投入できます。
2. **収録範囲を選ぶ**: 言語は自動判定されます。4 段階は小さい順にテキストのみ、常用、完全、すべて（ラテン文字フォントではテキストのみ、西欧、多言語、すべて）。各段階の文字数、ページあたりの推定ダウンロード量、ファイル数がその場で表示されます。ブログなら「常用」を選び、数本の記事を「あなたのテキスト」に貼り付けるのがおすすめです。記事に出てくる珍しい字が自動で追加され、よく使う字が先に読み込まれます。
3. **生成して配備**: 右側の計画パネルにページあたりの推定ダウンロード量、リクエスト数、シャードごとの読み込み確率が出ます。粒度スライダーを動かすと即座に更新されます。生成後にページへ文字を入力して試すと、ブラウザは該当するシャードだけをリクエストします。ZIP をダウンロードするか、プロジェクトのフォルダーへ直接書き込めます。

```text
<family>-webfont.zip
├─ fonts.css      @font-face + unicode-range、アップロードしたフォントのみ宣言
├─ fonts/         内容ハッシュ付きの WOFF2 シャード
├─ preload.html   プリロードタグ
├─ demo.html      シャードが必要に応じて読まれる様子を確認
├─ report.json    シャードごとの文字、サイズ、読み込み確率
└─ README.md      この生成に合わせた配備手順
```

配備方法は [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md) にまとめています。

## 特徴

- **頻度で分割**: 高頻度の文字は少数のファイルにまとめ、中頻度の領域は細かく切り、長い裾はコードポイント順に詰めます。基本文字は独立したシャードになり、プリロードを推奨します。粒度はスライダー 1 本で「通信量を減らす」から「ファイルを減らす」まで動かせます。
- **生成前に結果がわかる**: サイズモデルはそのフォントで 4 回実際にサブセット化して較正され、シャード総量の推定誤差は ±3.5% 以内。ページあたりの推定ダウンロード量は実測に対して −1%〜+4% に収まります。画面に出る数値はすべて計算結果です。
- **切り出すだけ**: CSS はアップロードしたフォントだけを宣言し、代替フォントもメトリクス上書きも入れません。代替のフォントスタックは利用者が自分の `font-family` で決めます。出力には内容ハッシュ付きのファイル名、プリロードタグ、配備手順、シャードごとのレポートが含まれます。ファイル名の接頭辞は既定でファミリー名から作られ、任意に指定もできます（例: `lxgw-400-87.f73f604a.woff2`）。パスと `font-display` は CSS にしか影響しないため、結果ページで変更するとコードと ZIP に即座に反映されます。
- **本物のオンデマンド読み込み体験**: 生成後にページへ文字を入力すると、ブラウザは `unicode-range` に一致するシャードだけを要求し、実際に要求されたファイルが画面に並びます。
- **標準文字集合に対応**: 汎用規範漢字表、台湾教育部の常用国字、香港常用字と HKSCS、Big5、GB 2312 / GBK / GB 18030、Unicode ブロック。簡体字と繁体字それぞれに頻度プロファイルがあります。
- **ラテン文字とコードフォント**: 漢字を含まないフォントと等幅フォントを自動判別し、文字体系ごとに分割し、リガチャ・スタイルセット・文字バリアントを保持します。
- **可変フォント**: 可変軸を保持するか、名前付きインスタンスから必要な固定スタイルだけを選んで出力できます。
- **マルチスレッド**: フォントの大きさと端末メモリからスレッド数を決めます。17 MB の Noto Sans SC Variable が 26 シャードを約 1 秒で生成します。
- **ローカル・オフライン**: バックエンドもテレメトリもありません。PWA なので初回アクセス後はオフラインでも動作します。中国語・英語の UI、ライト・ダークテーマ、スマートフォンでは展開できる下部の計画シートを備えます。

## プライバシーとライセンス

- バックエンドはありません。検査、サブセット化、WOFF2 エンコード、パッケージングはすべて現在のページの Web Worker と WASM の中で完結します。ブラウザが要求するのはアプリの資産、WASM、文字集合と頻度の JSON、そして Service Worker の更新だけです。
- `localStorage` に保存するのは UI の設定と文字・分割・出力の設定だけです。**ユーザーのテキストは決して保存しません。** フォント、シャード、ZIP はメモリと、利用者が自らダウンロードした場所にだけ存在します。
- **このツールはいかなるフォントの権利も付与しません。** サブセット化は通常「改変」に、Web 配備は通常「埋め込みと再配布」に当たります。商用フォントのライセンスの多くはこれを禁じているため、配備前に必ず確認してください。既定の「メタデータを削減」は Web ページが読まない `name` レコードだけを削除し、著作権・ファミリー名・ライセンスの説明とリンクは常に残します。

## 開発

Node.js 24+ と pnpm 11.24+ が必要です。

```bash
corepack enable
pnpm install          # ローカルで分割した wawoff2 WASM も生成
pnpm dev              # http://localhost:5173
pnpm check            # lint + アーキテクチャ検査 + 整形 + 単体テストとカバレッジ + データ検証 + ビルド
pnpm test:e2e         # 先にビルドしてから Playwright を実行（Chromium 全件、Firefox/WebKit は主要フロー）
pnpm benchmark:planner path/to/font.ttf --measure
```

`pnpm build` は純粋な静的 `dist/` を生成し、サブパスを含めどの静的ホスティングにも追加設定なしで配備できます。`master` へのプッシュ後は Woodpecker CI がビルドし、シンボリックリンクを原子的に切り替えて配備します。詳細は [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md) を参照してください。

## 対象外

- サーバー、CLI、ビルドプラグイン版。現在はブラウザアプリケーションのみです。
- TTC/OTC コレクションの分割。先に単一のフォントを書き出してください。
- 任意の可変軸座標やサブレンジ、`opsz` によるファミリー自動分割。
- グリフ編集、フォントの統合、フォーマット変換を超えるフォント改変。
