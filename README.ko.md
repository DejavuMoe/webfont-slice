# WebFont Slice

[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · **한국어** · [日本語](README.ja.md)

중국어·일본어·한국어 웹폰트를 필요할 때만 받아 쓰는 WOFF2 조각으로 나누고, 그대로 배포할 수 있는 `unicode-range` CSS를 만들어 줍니다. 라틴 문자 본문 폰트와 코드용 고정폭 폰트는 문자 체계별로 나누며, 합자와 스타일 세트는 그대로 유지합니다. 모든 처리는 브라우저 안에서만 이루어지고 폰트는 절대 업로드되지 않습니다.

소스 코드: <https://github.com/DejavuMoe/webfont-slice> (MIT)

![Noto Sans SC Variable을 불러온 WebFont Slice 작업 화면](docs/images/workbench-cjk.png)

CJK 폰트 하나가 보통 7–20 MB에 이릅니다. WebFont Slice는 실제 말뭉치 빈도로 각 글자가 페이지에 등장할 확률을 추정한 뒤, 동적 계획법으로 어디를 자를지 결정합니다. 그 결과 한 페이지는 실제로 그리는 글리프만 내려받습니다.

| 지원 범위 (Noto Sans SC Variable) | 글자 수 | 단일 파일(실측) | 글 문서 실제 다운로드(실측, 1,500자) | 단일 파일 대비 |
| --------------------------------- | ------: | --------------: | -----------------------------------: | -------------: |
| 자주 씀 (2013 표준 한자표 1급)    |   3,701 |          945 KB |                 810 KB · 파일 12.5개 |           −14% |
| 전체 (표준 한자표 전체)           |   8,306 |         2.13 MB |                 868 KB · 파일 14.9개 |           −60% |
| GBK (문자 집합 라이브러리)        |  21,124 |         5.37 MB |                 879 KB · 파일 15.1개 |           −84% |
| 모든 글자 (폰트 전체 글리프)      |  30,890 |         7.41 MB |                 891 KB · 파일 15.1개 |           −88% |

페이지당 다운로드량은 문자 집합 크기와 거의 무관합니다. 범위를 3천 자에서 3만 자로 늘려도 글 문서는 약 80 KB만 늘어납니다. 이 수치는 `pnpm benchmark:planner --measure`에서 나온 것으로, 모든 조각을 실제로 서브셋한 뒤 빈도로 기댓값을 계산합니다. 방법과 더 많은 폰트는 [`docs/SHARDING.md`](docs/SHARDING.md)를 참고하세요.

### 라틴 문자 폰트와 코드 폰트

한자가 없는 폰트(라틴 본문 폰트, JetBrains Mono나 Fira Code 같은 고정폭 코드 폰트, 아이콘이 들어 있는 Nerd Font)는 자동으로 인식합니다. 지원 범위는 유니코드 블록 기준 네 단계로 바뀝니다. 텍스트만, 서유럽, 다국어(라틴 확장·그리스·키릴 추가), 모든 글자입니다. 가운데 두 단계는 폰트에 실제로 있는 글자만 가져오므로, 수백 개의 유령 "누락" 글자가 생기지 않습니다. ASCII와 흔한 문장 부호는 기본 조각에 들어가고, 나머지는 문자 체계별로 묶입니다. 그리스, 키릴, 상자 그리기와 화살표, 사용자 정의 영역 아이콘이 각각 자기 조각을 가집니다. 순수 영어 페이지만 있다면 보통 기본 조각 하나만 받습니다.

| 폰트 (모든 글자)     | 글자 수 | 조각 수 | 단일 파일(실측) | 페이지가 보통 받는 양 |
| -------------------- | ------: | ------: | --------------: | --------------------: |
| JetBrains Mono 2.304 |   1,363 |       5 |           55 KB |       19 KB 기본 조각 |
| Fira Code 6.2        |   1,586 |       6 |           67 KB |       23 KB 기본 조각 |

고정폭 폰트는 별도로 표시됩니다. "레이아웃 기능 유지"가 켜져 있으면(기본값) `calt`/`liga` 합자에 더해 `ss01`–`ss20` 스타일 세트와 `cv01`–`cv99` 글자 변형도 유지되므로, 자기 CSS에서 `font-feature-settings`로 바꿀 수 있습니다. 생성되는 사용 예시는 고정폭 글꼴 패밀리를 `code, kbd, samp, pre`에 연결하고, 결과 페이지와 `demo.html`은 코드 샘플로 미리 보여 줍니다.

## 세 단계

1. **폰트 넣기**: TTF, OTF, WOFF, WOFF2를 파일 시그니처로 판별하며 개당 100 MB까지 지원합니다. 같은 패밀리의 여러 굵기를 한꺼번에 넣을 수 있습니다.
2. **지원 범위 고르기**: 언어는 자동으로 판단합니다. 네 단계는 작은 것부터 차례로 텍스트만, 자주 씀, 전체, 모든 글자입니다(라틴 폰트는 텍스트만, 서유럽, 다국어, 모든 글자). 각 단계의 글자 수, 페이지당 예상 다운로드, 파일 수가 실시간으로 표시됩니다. 블로그라면 "자주 씀"을 고르고 몇 편의 글을 "내 텍스트"에 붙여 넣는 것을 권합니다. 글에 나온 드문 글자가 자동으로 추가되고, 자주 쓰는 글자가 먼저 로드됩니다.
3. **생성하고 배포하기**: 오른쪽 계획 패널에 페이지당 예상 다운로드, 요청 수, 조각별 로드 확률이 나옵니다. 세분도 슬라이더를 끌면 즉시 갱신됩니다. 생성한 뒤 페이지에 글자를 입력해 보세요. 브라우저는 해당되는 조각만 요청합니다. ZIP으로 내려받거나 프로젝트 폴더에 바로 쓸 수 있습니다.

```text
<family>-webfont.zip
├─ fonts.css      @font-face + unicode-range, 해당 폰트만 선언
├─ fonts/         내용 해시가 붙은 WOFF2 조각
├─ preload.html   프리로드 태그
├─ demo.html      조각이 필요할 때 로드되는 모습 보기
├─ report.json    조각별 글자, 크기, 로드 확률
└─ README.md      이번 생성에 맞춘 배포 안내
```

배포 방법은 [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md)에 정리되어 있습니다.

![결과 페이지: 이 예시 텍스트에서는 26개 중 7개 조각만 요청되었습니다](docs/images/result.png)

## 특징

- **빈도로 나눈 조각**: 자주 쓰는 글자는 몇 개의 파일로 합치고, 중간 빈도 구간은 잘게 나누고, 긴 꼬리는 코드 포인트 순서로 묶습니다. 기본 글자는 따로 조각을 만들고 프리로드를 권장합니다. 슬라이더 하나로 "바이트 적게"부터 "파일 적게"까지 조절합니다.
- **생성 전에 결과를 알 수 있음**: 크기 모델은 해당 폰트로 실제 서브셋을 네 번 돌려 보정하며, 조각 총량 추정 오차는 ±3.5% 안쪽입니다. 페이지당 예상 다운로드는 실측 대비 −1%에서 +4% 사이입니다. 화면에 보이는 모든 수치는 계산된 값입니다.
- **자르기만 함**: CSS는 업로드한 폰트만 선언하며 대체 폰트도, 메트릭 재정의도 넣지 않습니다. 대체 폰트 스택은 사용자가 자기 `font-family`에서 정합니다. 결과물에는 내용 해시 파일명, 프리로드 태그, 배포 안내, 조각별 보고서가 포함됩니다. 파일명 접두사는 기본으로 패밀리 이름에서 가져오며 직접 지정할 수도 있습니다(`lxgw-400-87.f73f604a.woff2`). 경로와 `font-display`는 CSS에만 영향을 주므로 결과 페이지에서 바꾸면 코드와 ZIP에 즉시 반영됩니다.
- **진짜 주문형 로딩 체험**: 생성한 뒤 페이지에 글자를 입력하면 브라우저가 `unicode-range`에 맞는 조각만 요청하고, 화면에 실제로 요청된 파일이 나열됩니다.
- **표준 문자 집합 지원**: 《通用规范汉字表》, 대만 교육부 상용 국자, 홍콩 상용자와 HKSCS, Big5, GB 2312 / GBK / GB 18030, 유니코드 블록. 간체와 번체에 각각 빈도 프로필이 있습니다.
- **라틴 문자와 코드 폰트**: 한자가 없는 폰트와 고정폭 폰트를 자동 인식하고, 문자 체계별로 나누며, 합자·스타일 세트·글자 변형을 유지합니다.
- **가변 폰트**: 가변 축을 유지하거나, 이름 있는 인스턴스 중 필요한 고정 스타일만 골라 낼 수 있습니다.
- **멀티스레드**: 폰트 크기와 기기 메모리에 따라 스레드 수를 정합니다. 17 MB짜리 Noto Sans SC Variable이 조각 26개를 약 1초에 만듭니다.
- **로컬, 오프라인**: 백엔드도 텔레메트리도 없습니다. PWA라서 처음 방문한 뒤에는 오프라인에서도 동작합니다. 중국어·영어 인터페이스, 라이트·다크 테마, 휴대폰에서는 펼칠 수 있는 하단 계획 시트를 제공합니다.

## 개인정보와 라이선스

- 백엔드가 없습니다. 검사, 서브셋, WOFF2 인코딩, 압축은 모두 현재 페이지의 Web Worker와 WASM 안에서 끝납니다. 브라우저는 앱 자산, WASM, 문자 집합·빈도 JSON, Service Worker 업데이트만 요청합니다.
- `localStorage`에는 인터페이스 환경설정과 문자/분할/출력 설정만 저장하며 **사용자 텍스트는 절대 저장하지 않습니다**. 폰트, 조각, ZIP은 메모리와 사용자가 직접 내려받은 위치에만 존재합니다.
- **이 도구는 어떤 폰트 권리도 부여하지 않습니다.** 서브셋은 보통 수정으로, 웹 배포는 보통 임베딩과 재배포로 간주됩니다. 상용 폰트 라이선스 상당수가 이를 금지하므로 배포 전에 반드시 확인하세요. 기본값인 "메타데이터 정리"는 웹 페이지가 읽지 않는 `name` 레코드만 지우며, 저작권·패밀리·라이선스 설명과 링크는 항상 유지합니다.

## 개발

Node.js 24+와 pnpm 11.24+가 필요합니다.

```bash
corepack enable
pnpm install          # 로컬에서 분할한 wawoff2 WASM도 함께 생성
pnpm dev              # http://localhost:5173
pnpm check            # lint + 아키텍처 프로브 + 포맷 + 단위 테스트와 커버리지 + 데이터 검증 + 빌드
pnpm test:e2e         # 먼저 빌드한 뒤 Playwright 실행 (Chromium 전체, Firefox/WebKit 주요 흐름)
pnpm benchmark:planner path/to/font.ttf --measure
```

`pnpm build`는 순수 정적 `dist/`를 만들며, 하위 경로를 포함해 어떤 정적 호스팅에도 별도 설정 없이 배포할 수 있습니다.
